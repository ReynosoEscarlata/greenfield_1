## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gap between ticket-number digits/labels if needed |
| sm | 8px | Gap between cards in the ventanillas grid (small screens), internal card padding edges |
| md | 16px | Default padding inside queue strip and ventanilla cards |
| lg | 24px | Section padding (top-level page padding, gap between queue strip and ventanillas grid) |
| xl | 32px | Layout gaps — outer page margin on desktop |
| 2xl | 48px | Major section breaks — not used in this phase (reserved for later phases with denser content) |
| 3xl | 64px | Page-level spacing — not used in this phase |

Exceptions: none for this phase. No interactive touch targets exist yet (buttons arrive in Phase 2+); this phase only needs static placeholder regions.

## Typography

This phase establishes the baseline type scale. Later phases (especially Phase 7, Distance-Readable Display) will introduce a larger "display" size for ticket numbers — declared here as a placeholder size so Phase 1's shell doesn't need restyling later, but not yet applied to real ticket data (no ticket data exists until Phase 2).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 (regular) | 1.5 |
| Label | 14px | 400 (regular) | 1.5 |
| Heading | 20px | 600 (semibold) | 1.2 |
| Display | 28px | 600 (semibold) | 1.2 |

Notes:
- Exactly 4 sizes (14/16/20/28), exactly 2 weights (400/600) — per design contract limits.
- "Display" (28px) is reserved for the page title "Turnero" in this phase (D-03). It is NOT yet used for ticket numbers — Phase 7 will likely require a larger dedicated display size for distance-readability (DISPLAY-01: legible at 3 meters) and may introduce a new token at that time. Do not over-apply 28px to placeholder card content in this phase.
- Placeholder text inside queue strip and ventanilla cards uses Label (14px) or Body (16px) — these are throwaway scaffold placeholders, not final ticket displays.

## Color

This phase is grayscale/neutral only — no semantic color usage yet (no destructive actions, no call-state feedback exist until Phase 3+). Colors below establish the baseline page chrome.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | #FFFFFF | Page background |
| Secondary (30%) | #F1F3F5 | Queue strip background, ventanilla card background (distinguishes regions from page background) |
| Accent (10%) | #1F2933 (dark neutral, not a true "color" accent) | Page title "Turnero" text, section headings — used only for the title and the two section labels ("Cola" / "Ventanillas" if rendered), nothing else |
| Destructive | not applicable this phase | No destructive actions exist until Phase 3 (WINDOW-02 remove-ventanilla blocking). Will be declared in Phase 3's UI-SPEC. |

Accent reserved for: the "Turnero" page title text and the two placeholder section headings ("Cola" and "Ventanillas" labels, or equivalent). Not used on any other element in this phase — there are no buttons, badges, or interactive elements yet.

## Layout Contract (Phase-specific addition)

Captures D-01 from 01-CONTEXT.md so the executor has an unambiguous structural reference.

| Region | Position | Structure |
|--------|----------|-----------|
| Page title | Top of page, above queue strip | `<h1>` "Turnero", Display size (28px/600/1.2), accent color |
| Queue placeholder | Horizontal strip, directly below title | Full-width block, Secondary background (#F1F3F5), `lg` (24px) padding, contains heading "Cola" + placeholder body text |
| Ventanillas placeholder | Below queue strip | CSS grid of cards, `md` (16px) gap, auto-fit columns (e.g. `repeat(auto-fit, minmax(200px, 1fr))`); each card uses Secondary background, `md` (16px) internal padding; section preceded by heading "Ventanillas" |
| Page container | Wraps title + both regions | Max content width reasonable for a waiting-room display (e.g. `1200px`, centered), `xl` (32px) outer padding on desktop, `lg` (24px) on smaller viewports |

This is a single static page — no responsive breakpoint system is required yet (no interactive elements to break), but the grid's `auto-fit`/`minmax` approach naturally reflows card count without a media query, satisfying "doesn't look broken on a smaller window" without extra scope.
