## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User click → dispatch | Button clicks are the only input path; no user-typed text, no external data |
| VentanillaCard local state | showWarning is ephemeral local state; cannot be tampered with by other components |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-04 | Tampering | WINDOW-02 UI guard in VentanillaCard | accept | Guard is UI-only; a user who bypasses the UI (e.g., via DevTools dispatch) can force-remove a window with an active ticket. Acceptable: this is a local single-user display, no auth in scope, no PII at risk |
| T-03-05 | Tampering | React key=v.id on VentanillaCard | mitigate | Use v.id (stable, ever-incrementing integer) as React key — not array index. Prevents React from reusing component instances when windows are removed, which would cause stale showWarning state to appear on the wrong card |
| T-03-06 | Information Disclosure | .ventanilla-warning text | accept | Warning message "No se puede quitar: tiene un turno activo" discloses that a ticket is active — this is intentional UX, not a leak (PRIVACY-01 is scoped to Phase 7 and concerns patient names, not ticket status) |
</threat_model>
