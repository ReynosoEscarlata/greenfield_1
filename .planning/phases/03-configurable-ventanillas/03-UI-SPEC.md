|---------------------|------------|-------------|

## Copywriting Contract

| Element | Copy |
|---------|------|
| Add window CTA | "Agregar ventanilla" |
| Remove button aria-label | "Quitar ventanilla {N}" (e.g. "Quitar ventanilla 1") |
| Card heading | "Ventanilla {N}" (e.g. "Ventanilla 1", "Ventanilla 3" — number never reused) |
| Empty ticket state (per card) | "sin turno" — all lowercase, canonical string per D-09. Covers first-load and post-removal states. |
| Active ticket state (per card) | "Turno {N}" (e.g. "Turno 5") — set by Phase 4, displayed by Phase 3. |
| Empty grid state (no windows) | "Presiona Agregar ventanilla para comenzar" |
| WINDOW-02 guard message | "No se puede quitar: tiene un turno activo" |
| Section heading | "Ventanillas" (existing `<h2>` content, unchanged) |

Destructive actions in this phase: removing a ventanilla is the closest to destructive. Confirmation approach: none — WINDOW-02 guard blocks the action with an inline warning when `currentTicket !== null`. There is no confirmation dialog, no `alert()`, no `window.confirm()`. The remove button for an idle (no ticket) ventanilla dispatches immediately with no confirmation step.

> Source: CONTEXT.md D-09 ("sin turno"), D-08 ("Ventanilla N"), RESEARCH.md Pattern 4 (warning copy), RESEARCH.md Pattern 5 (empty grid copy), REQUIREMENTS.md WINDOW-02.

## Interaction Contract

| Action | Trigger | Outcome |
|--------|---------|---------|
| Add ventanilla | Click "Agregar ventanilla" | Dispatches `ADD_WINDOW`. New card appears at end of grid. `nextWindowNumber` increments; number is never reused (D-10). |
| Remove ventanilla (idle) | Click "×" on card with `currentTicket === null` | Dispatches `REMOVE_WINDOW`. Card disappears from grid. No confirmation dialog. |
| Remove ventanilla (active ticket) | Click "×" on card with `currentTicket !== null` | No dispatch. Sets local `showWarning = true`. Inline `.ventanilla-warning` appears below the remove button. |
| Warning persistence | — | Warning stays visible until next interaction. No auto-dismiss in this phase (deferred to Phase 6). |
| Phase 4 forward-compatibility | Phase 4 calls `CALL_NEXT` | Sets `ventanilla.currentTicket` to a `Ticket`. Phase 3 already reads this field and renders "Turno N". No Phase 3 UI changes needed. |

> Source: CONTEXT.md (Claude's Discretion — control placement, warning form), RESEARCH.md Pattern 3 and Pattern 4.
