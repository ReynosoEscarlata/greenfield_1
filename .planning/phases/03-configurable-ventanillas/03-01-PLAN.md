## Phase Goal

**As a** clinic operator, **I want to** add and remove call windows and see each window's ticket state, **so that** I can configure the display board to match how many windows are in operation.

<objective>
This plan lays the state and test infrastructure for Phase 3. It extends the reducer with the Ventanilla type, the two new reducer cases, and the critical ADD_TICKET spread fix. It also creates the App.test.tsx integration test scaffold (intentionally failing until Plan 02 implements the UI) and adds the missing "test" npm script.

Purpose: Without this plan, Plan 02 has no type contracts to build against and no test suite to verify against. The ADD_TICKET spread fix must land here — before the UI is wired — or any ticket added after a window operation will silently drop the window state.

Output: Extended src/turnero.ts (Ventanilla type, QueueState with ventanillas/nextWindowNumber, fixed ADD_TICKET, ADD_WINDOW/REMOVE_WINDOW cases), extended src/turnero.test.ts (5 new reducer unit tests), new src/App.test.tsx (3 integration test stubs — Red until Plan 02), package.json with "test" script.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Tampering | ADD_TICKET case in queueReducer | mitigate | Spread `...state` in return so all QueueState fields are preserved atomically — the bug fix is the mitigation |
| T-03-02 | Tampering | REMOVE_WINDOW reducer | accept | Reducer removes unconditionally; guard lives in UI component (VentanillaCard). A user interacting with the DOM directly bypasses the UI guard but cannot corrupt state beyond removing a window — acceptable for a local clinic display with no auth requirement |
| T-03-03 | Denial of Service | ADD_WINDOW (no upper bound) | accept | No practical upper bound on ventanilla count; for a single-tab local clinic display, unlimited add is not a meaningful attack surface |
</threat_model>
