## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User browser input → React dispatch | User initiates ADD_TICKET via button click. The click event carries no payload — there is no user-supplied text, number, or string crossing this boundary. The entire "input" is the click itself. |
| React state → DOM render | state.queue elements are TypeScript Ticket objects with integer fields. The JSX renders `Turno {ticket.number}` where ticket.number is a number type — never a user-authored string. React's JSX auto-escaping is the render boundary. |
| npm registry → project devDependencies | Four devDependencies enter the build toolchain in Wave 0 from the public npm registry. Affects the development environment only; not included in the production bundle. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Information Disclosure | Rendered queue chips | accept | Ticket content is always "Turno {N}" where N is a TypeScript integer generated by the reducer. No user-supplied text is ever rendered anywhere in this phase. PRIVACY-01 (no PII on screen) is satisfied by construction — this phase introduces zero text-input fields. No action required. |
| T-02-02 | Denial of Service | "Agregar turno" button / in-memory queue array | accept | Rapid clicking grows the in-memory queue array. Acceptable risk: this is a single-user, single-tab, no-backend app; the practical ceiling is browser memory (>100MB for a JS array of small objects). No rate-limiting, debounce, or queue-size cap is required at this scope. Scope explicitly excludes multi-user and multi-device scenarios. |
| T-02-03 | Tampering | React useReducer state via DevTools | accept | A developer with browser DevTools can pause JS execution or monkey-patch React internals to modify component state. Acceptable: no authentication boundary exists, no PII is at risk, and any user with physical access to the device can legitimately operate all controls (per PROJECT.md intent — no auth, no roles). |
| T-02-04 | Tampering | JSX render / dangerouslySetInnerHTML | mitigate | No dangerouslySetInnerHTML is used or permitted in this phase. All ticket content is `Turno {ticket.number}` where ticket.number is a TypeScript number — never a user-provided string. React JSX auto-escapes all interpolated children. Enforcement: `grep -r "dangerouslySetInnerHTML" src/` must return 0 matches before phase completion. |
| T-02-05 | Spoofing / Elevation of Privilege | Authentication / session | accept | Explicitly out of scope per CLAUDE.md and REQUIREMENTS.md. No auth, no roles, no sessions. Any operator of the device can use all controls — this is the intended design. |
| T-02-SC | Tampering | npm devDependency install (Wave 0) | mitigate | All four Wave 0 packages (vitest, @testing-library/react, @testing-library/jest-dom, jsdom) are treated as [ASSUMED] — RESEARCH.md contains no Package Legitimacy Audit table.
