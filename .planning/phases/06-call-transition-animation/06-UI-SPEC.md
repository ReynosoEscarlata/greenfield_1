## Color

Pre-populated from src/index.css. One new animation-specific color is introduced.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | #ffffff | Page background (body) |
| Secondary (30%) | #f1f3f5 | Cards (.ventanillas-grid > *), queue strip, buttons |
| Text (universal) | #1f2933 | All text — headings, body, labels, ticket numbers |
| Muted | #6b7c93 | .ventanilla-remove button text only |
| Destructive | #c0392b | .ventanilla-warning text only (removal block + empty queue) |
| Animation flash (accent) | #fbbf24 | `.ventanilla-ticket-flash` @keyframes `from` value ONLY |

**Accent reserved for:** the `background-color` of `.ventanilla-ticket` at frame 0 of the
`ticket-flash` animation, and nowhere else. It is not used on any button, border, or
persistent UI surface.

**Why #fbbf24:** Warm amber (Tailwind amber-400) against the #f1f3f5 card background produces
a high-visibility flash readable from a distance without clashing with the #c0392b destructive
color. The flash fades to `transparent` so the card background shows through at rest.

## Animation Contract

All decisions locked from CONTEXT.md (D-01 through D-07).

### @keyframes Rule

```css
@keyframes ticket-flash {
  from {
    background-color: #fbbf24;
  }
  to {
    background-color: transparent;
  }
}
```

- Name: `ticket-flash`
- Property animated: `background-color` only (text color #1f2933 unchanged throughout)
- From value: `#fbbf24` (warm amber — full flash color)
- To value: `transparent` (inherits card background #f1f3f5 at rest)
- Duration: 600ms (center of suggested 500-800ms range — enough to notice, short enough not to annoy on rapid calls)
- Timing function: `ease-out` (fast impact on entry, graceful fade-off — matches "something just changed" perception)
- Fill mode: `forwards` (element rests at the `to` state after animation completes)

### CSS Class

```css
.ventanilla-ticket-flash {
  animation: ticket-flash 600ms ease-out forwards;
  border-radius: 4px;
}
```

`border-radius: 4px` prevents the amber highlight from appearing as a hard-edged rectangle
against the card background. The existing `.ventanilla-ticket` margin and padding are unchanged.

### Trigger Mechanism (D-04)

Apply `key={ventanilla.currentTicket?.id ?? 'empty'}` to the `<p className="ventanilla-ticket">`
element in `VentanillaCard`. React unmounts and remounts the element when the key changes,
resetting CSS animation state automatically. No `animationend` listener, no extra state.

Apply `.ventanilla-ticket-flash` class conditionally — only when `ventanilla.currentTicket !== null`.

```jsx
<p
  key={ventanilla.currentTicket?.id ?? 'empty'}
  className={
    ventanilla.currentTicket !== null
      ? 'ventanilla-ticket ventanilla-ticket-flash'
      : 'ventanilla-ticket'
  }
>
  {ventanilla.currentTicket === null
    ? 'sin turno'
    : `Turno ${ventanilla.currentTicket.number}`}
</p>
```

### Behavior Table

| Transition | Key changes? | Flash class? | Animation fires? | Requirement |
|------------|-------------|--------------|-----------------|-------------|
| null → ticket (call succeeds) | yes (empty → id) | yes | yes | D-01, D-04 |
| ticket A → ticket B (rapid call) | yes (id-A → id-B) | yes | yes, restarts from frame 0 | D-05 |
| ticket → null (external clear) | yes (id → empty) | no | no | D-07 |
| page load / reload with ticket | no (first mount) | yes (if non-null) | no (first mount has no prior key) | D-06 |
| queue empty — call pressed | no (no state change) | n/a | no | D-07 |

### Scope (D-03)

Animation is scoped to `<p className="ventanilla-ticket">` inside the card. The `.ventanilla-card`
container, `.ventanilla-label`, `.ventanilla-remove`, and `.call-next-button` are not animated.

### No Animation Library (D-02)

Pure CSS `@keyframes`. No `framer-motion`, no `react-transition-group`, no `motion` package.
Per CLAUDE.md "What NOT to Use" — CSS transitions/`@keyframes` are explicitly recommended for
this exact use case.
